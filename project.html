01 / El problema

Antes de diseñar una pantalla, una pregunta.

¿Cómo ayudar a una persona a entender su dinero sin exigirle que se convierta en experta? Este concepto parte de esa pregunta. La hipótesis: una experiencia financiera debe explicar, acompañar y dejar el control en manos de quien la usa.

Preguntas de investigación

  • ¿Qué necesita entender alguien antes de conectar su cuenta?
  • ¿Qué información ayuda a tomar una decisión hoy?
  • ¿Cómo comunicar una sugerencia sin generar presión?

Visual conceptual para ilustrar la estructura del caso.

02 / La experiencia

La confianza se construye paso a paso.

La propuesta separa explorar, conectar y decidir. Cada paso explica su propósito; los permisos aparecen cuando se necesitan. El flujo es una hipótesis para probar, no una conclusión de investigación.

ExplorarEntender el valor antes de compartir datos.
ConectarPermisos claros, control en cada paso.
DecidirUna recomendación y una acción concreta.

Visual conceptual para ilustrar la estructura del caso.

03 / La interfaz

Una vista para entender. Un gesto para actuar.

La jerarquía comienza con el saldo y termina con una sugerencia accionable. Los tonos suaves, el lenguaje directo y las metas visibles exploran una relación más tranquila con el dinero. Las cifras de la maqueta son datos ficticios.

04 / Qué validar

La siguiente decisión necesita evidencia.

El siguiente paso sería probar comprensión, navegación y confianza con personas. El caso real documentará qué cambió después de cada prueba, qué aprendimos y qué quedó pendiente.

Evidencia para el caso real

  • Síntesis de entrevistas y criterios de diseño.
  • Flujo inicial, pruebas de tareas y cambios al prototipo.
  • Resultados observados, limitaciones y siguiente iteración.
